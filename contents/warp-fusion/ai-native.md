# WarpFusion：AI Native 引擎

> 判断一门语言对 AI 是否友好，看的不是语料多不多，而是三件事：**语言表面积**（越小越易一次生成正确）、**语义明确度**（越显式歧义越少）、**验证反馈速度**（越快越能形成「生成 → 验证 → 修正」闭环）。

先把概念说清楚，避免误读：

> WarpFusion 说自己是 AI Native 引擎，**不是指引擎内置大模型**，而是指从语言到工具链，整条「规则开发 → 验证 → 上线」流水线都**按「AI 是一等参与者」来设计**：让 AI 写规则、让引擎证明对错、让机器可读的回执驱动 AI 自我迭代，并用人机双重的门禁兜底。

---

## 一、为什么引擎需要「AI Native」

AI 辅助编码普及之后，检测规则开发的瓶颈发生了迁移：

| 环节 | 变化 |
|---|---|
| **编写** | 已被 AI 大幅压缩为低成本动作——对 WFL 与 Java/SQL 同等加速，不再是差异点 |
| **验证** | AI 没有让「验对」变快：WFL 规则内联 `test` 写完即验（秒级）；Flink 侧即便 AI 秒出代码，仍需起环境、造数据、编译、部署 job 才能确认对错 |
| **上线** | WFL 热加载即时生效；Flink 每规则一次 job 生命周期 |

于是分水岭后移到验证与上线——而这正是语言设计可以决定的部分：

| AI 友好度要素 | WFL | Flink（Java / SQL） |
|---|---|---|
| **语言表面积** | 一条规则**几行**声明式代码（五原语：Bind / Match / Stats / Join / Yield） | 数百行 Java DataStream，或嵌套 SQL + 大量隐式约定（状态、水位、并行度、序列化） |
| **语义明确度** | 显式：`entity` / `score` / `match` / `stats` 各有独立语义与编译期校验 | 隐式约定多，出错面大 |
| **验证反馈速度** | 内联 `test` **秒级**验证命中 / 未命中 | 需起环境、造数据、部署 job，之后才知道「能不能正确运行」 |

**结论**：AI 把「写出来」变快了，WarpFusion 让「验对 + 上线」也快——两者叠加，规则迭代的端到端周期才真正被压缩。

## 二、语言侧：为「一次生成正确」而设计

- **少而强**：WFL 只有五个原语，语法糖在编译期全部归一为唯一语义内核——语言足够小，AI 单次生成的成功率足够高；
- **语义显式可检查**：`entity` / `score` / `match` / `stats` / `join` 各有确定语义与校验，很多错误在**编译期**暴露而非运行期；
- **测试与规则同文件**：`test ... for ...` 块直接写在 `.wfl` 里，AI 改规则时契约同步可见——`expect` 是**独立语义 oracle**，AI 改了规则没跟着改期望，测试就 FAIL。

```wfl
test full_chain for chain_attack {
  input {
    row(scan, sip = "10.0.0.1", ... action = "syn",        event_time = "2026-01-01T00:00:00Z");
    row(login, sip = "10.0.0.1", ... action = "login_fail", event_time = "2026-01-01T00:00:05Z");
  }
  expect { hits == 1; hit[0].score == 90.0; hit[0].entity_id == "10.0.0.1"; }
}
```

## 三、验证侧：AI 原生规则开发闭环（6 级，已落地 · alpha 2026-09）

引擎侧把「AI 写规则 → 自动验证 → 结构化回执」做成一等公民工作流，逐级回答「规则对不对」：

| # | 能力 | 命令 | 解决的问题 |
|---|---|---|---|
| 0 | **编译期检查** | `wfl lint` / `wfl explain` | 语法 / 类型错误在运行前拦住；编译后形态人 / AI 可读 |
| 1 | **语义自证（契约测试）** | `wfl test` | 逐条 `expect` 证明「规则按作者意图执行」（引擎状态机进程内执行，秒级） |
| 2 | **对抗测试生成** | `wfl test --gen-negatives` | 机器从规则结构**静态反演**反例，断言独立于 AI 写的 expect——打破「AI 写规则 + AI 自证」循环 |
| 3 | **检测意图验证** | `wfl intent`（`.wfi` 正 / 负样本集） | 证明「意图本身对」：正样本 0 命中 → 漏报 FAIL；负样本命中 → 误报 FAIL |
| 4 | **真实回放 / 对拍** | `wfl replay` / `wfl verify` | 真实数据流 + oracle 逐条比对（支持 score / time 容差） |
| 5 | **性能护栏** | `wfgen perf-diag --gate` | 语义对还不够，**性能可接受才放行**：绝对阈值兜底 + 相对基线防回归 |

设计要点（每条都对应「防 AI 自证」的护栏）：

- **expect 是独立语义 oracle**：AI 改规则没跟着改期望，测试就 FAIL——验证不依赖 AI 的判断；
- **对抗样本由机器补**：L2 从 bind guard（`field == literal` / `field != literal`）反演反例行追加，断言「反例行被过滤、hits 不变」；
- **漏报 / 误报可测**：`.wfi` 正负样本分类严格 canonical，`hits == 5` / `>= 3` / 正负断言并存等自相矛盾样本明确报错，**不静默归类**；样本写错（引用不存在字段 / alias）单列 `errors`，不虚增漏报 / 误报；
- **性能门禁防静默失效**：空门禁 / 拼错 key（`deny_unknown_fields`）/ 负阈值 / 与基线录制同给——全部显式报错；门禁开着却「没拦任何东西」不允许存在。

## 四、回执契约：让 AI 自己读懂「差在哪」

所有验证命令输出**版本化、机器可读的回执**，`verdict` 与退出码一致——AI 和 CI 可以按退出码直接拦截，也可以读 JSON 明细自我修正：

| 命令 | 回执 schema | verdict 依据 |
|---|---|---|
| `wfl test --format json` | `wfl-test-report/v1` | `summary.failed > 0` → FAIL |
| `wfl intent --format json` | `wfl-intent-report/v1` | 同上；附 `false_negatives` / `false_positives` / `errors` 计数 |
| `wfgen perf-diag --format json` | `wfgen-perf-report/v1` | 门禁任一 check FAIL → FAIL |

失败项一律**自解释**（stdout 纯净单份 JSON，进度 / 错误走 stderr）：

```
漏报：正样本应触发（expect hits >= 1），实际 0 命中——规则漏检该输入
hits: expected hits == 0, got 1
rules 档 EPS=150000 vs 基线 200000（回退 25.0%，允许 ≤20.0%）
```

这意味着「AI 生成 → 引擎回执指出差在哪 → AI 据回执修改 → 再验证」可以闭环自动跑——人只负责定意图与验收标准。

## 五、生态设施

| 设施 | 内容 |
|---|---|
| **`wf-skills` 技能包** | 面向 Claude Code / Codex 的规则开发技能（规则编写与 lint、`.wfs` schema、运行配置、测试管线调试、性能基准验证、系统集成接入等），一键安装进 `~/.claude/skills` 或 `~/.codex/skills` |
| **`wf-rules` 规则语料** | 18 条真实 `.wfl` 检测规则，按攻击阶段组织（侦察 / 初始访问 / 横向移动 / C2 / 外传 / 链式组合等），作为 few-shot 语料与回归基线 |
| **编辑器 / LSP** | `tree-sitter-wfl` 语法高亮（Zed 扩展）+ WFL LSP（诊断 / 跳转 / 补全），在编辑器内即时校验——AI 与人共用同一反馈通道 |
| **`wfgen` 确定性数据生成** | 同 `count + seed` 字节级确定；`.wfg` 场景文件生成带**命中 / 近失 / 未命中**三类样本——既是回归样本，也是 AI 练习与验收的数据源 |

## 六、诚实的边界（AI Native 的「不做什么」）

- **AI 生成 ≠ 免验证**：检测规则出错是**静默**的（漏报 / 误报不报错）。生成的规则必须跑 `wfl test` 并纳入回归——这是底线，不是建议；
- **不做自动修规则**：闭环只承诺「回执能证明规则对在哪、错在哪」；自动修复是回执之上的策略层，由用户决定是否引入；
- **如实覆盖，不虚报**：L2 对抗反例只覆盖简单 bind guard，复合 guard（函数 / 嵌套 / 逻辑组合）如实跳过，回执不会假装覆盖；
- **性能门禁需本地校准**：L5 绝对阈值与机器相关，须在目标机 `--record-baseline` 校准；相对回归跨机器稳健；
- **现状**：AI 原生开发闭环为 alpha（2026-09），统一合并回执命令（lint + test + intent + perf 一次出单份 verdict）、消费侧接入等仍在演进；
- **人的位置**：AI 负责速度，人负责方向——规则**意图**（`.wfi` 正 / 负样本）与验收标准仍需由人来定义。
