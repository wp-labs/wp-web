核心技术创新

技术路线创新 × Rust 工程 × 领域 DSL

两种技术路径的本质差异

从"文本匹配"到"结构解析"的技术路线转变

📍 路径 1：正则匹配思路

行业主流 20 年

技术路线

原始日志 → 正则引擎匹配 → 捕获组提取 → 字符串分配 → 结果
         ↑多次尝试匹配  ↑每个字段一次  ↑频繁拷贝

代表产品
• GROK (Logstash): Ruby Oniguruma，支持回溯/递归/环视，复杂场景性能不可控
• VRL (Vector): Rust regex，已避免回溯，但仍需多次正则匹配 + 字符串分配

APT 场景实测
• CPU: 794%
• EPS: 18.9K

🚀 路径 2：结构化解析思路

WarpParse 首创

技术路线

原始日志 → 结构化解析 → 对象构建 → 结果
         ↑一次扫描      ↑零拷贝

关键技术
• 解析器组合子 (Winnow): 类似编程语言解析器的确定性解析技术
• 一次扫描完成: 不需要多次匹配尝试，确定性解析路径
• 零拷贝架构: 详见 Page 30 工程优化

APT 场景实测
• CPU: 558%
• EPS: 129.6K (6.86x)

核心价值: 将解析器组合子技术首次系统性应用到日志解析

选择了更适合结构化数据的技术路线

🔒 专利保护: PCT/CN2026/072658

WPL 解析语言

专为日志解析设计的领域语言

同一解析任务对比：Nginx 日志

❌ Logstash GROK (248B)

%{IPORHOST:clientip} - - \[%{HTTPDATE:timestamp}\] "%{WORD:method} %{URIPATHPARAM:request} %{NUMBER:status} %{NUMBER:bytes} "%{DATA:referrer}" "%{DATA:agent}"

✅ WPL (174B)

( ip:clientip, 2*_, time:timestamp<[,]>, http/method", http/request", digit:status, digit:size, chars:referer", http/agent", _" )

体积减少 30% · 可读性提升 10倍

🚀 核心价值

WPL 为日志解析提供确定的最优路径、丰富的结构化表达能力和极高的表达效率——
使用者学习成本、编写成本、维护成本均达到最低。

技术路径对比

• GROK：正则匹配，支持回溯，复杂场景性能不可控
• VRL：正则匹配，已避免回溯，但仍需多次正则匹配 + 字符串分配
• WPL：解析器组合子，确定性解析路径，一次扫描完成
