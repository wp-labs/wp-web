核心特性

M

跨事件的模式匹配

能力内核是跨多条事件、跨时间窗口的关联计算，而非单条过滤： 输入结构化事件流，输出满足关联条件的告警 / 评分 / 结构化数据。

L

WFL 声明式语言

五原语（Bind / Match / Stats / Join / Yield）说清「要找什么」； 三文件模型把「数据长什么样 / 匹配什么 / 怎么跑」分离，各角色各改各的。

B

单二进制 · 零依赖

Rust 编写，一个二进制跑完完整链路：不依赖 Kafka、etcd 或数据库， 一台 8GB 节点即可承载约千条规则，空载内存目标 <100MB。

T

规则自带测试

`test` 块写在规则文件里：命中 / 未命中一键验证，秒级反馈； replay / verify / wfgen 构成完整验证闭环，写完即验证，不靠祈祷。

A

AI Native

语言为 AI 生成而设计：小表面积、显式语义、机器可读回执， 「AI 写规则 → 引擎证明对错 → 回执驱动自迭代」是一等公民工作流。

R

可解释 · 带评分

实体建模 entity() + 数值评分 score() + stat.* 证据字段， 把「为什么触发」输出为可审计的告警证据，而非黑盒命中。

它是什么、不是什么 —— 品类边界

是：实时关联计算 / 模式匹配引擎 不是（请诚实回避）
跨数据源、跨时间窗口、跨步骤的有状态关联 通用分布式流计算平台（无分布式协调 / checkpoint）
WFL 声明式规则 + 自带测试闭环 + 热加载 数据仓库 / 交互式分析引擎（无行保留聚合，交下游 SIEM）

规则能力

WFL 把检测语义做成语言一等公民：时序链、缺失检测、实体建模、评分、窗口统计与关联 —— 一条规则说清「要找什么」

五原语 · WFL —— 一条规则说清一条攻击链

chain_attack.wfl规则即测试载体 
// 同一 IP：30 分钟内既扫 5 个端口、又失败登录 3 次 → 评分 90
rule chain_attack {
    events {
        scan  : conn_events && action == "syn"
        login : conn_events && action == "login_fail"
    }
    match<sip:30m> {
        on event {
            scan  | count >= 5;
            login | count >= 3;
        }
    } -> score(90.0)
    entity(ip, scan.sip)
    yield network_alerts (sip = scan.sip, alert_type = "chain_attack")
}
同一文件内的 test写完即验 
// expect 是独立语义 oracle：AI 改了规则没改期望 → FAIL
test full_chain for chain_attack {
  input {
    row(scan,  sip = "10.0.0.1", action = "syn",        event_time = "2026-01-01T00:00:00Z");
    row(login, sip = "10.0.0.1", action = "login_fail", event_time = "2026-01-01T00:00:05Z");
  }
  expect {
    hits == 1;
    hit[0].score == 90.0;
    hit[0].entity_id == "10.0.0.1";
  }
}
// wfl test rules/chain_attack.wfl --schemas "schemas/*.wfs"

WarpFusion 是 AI Native 引擎

AI Native ≠ 内置大模型：引擎配置、规则编写、验证、度量——通过 AI 都能完成

配置（wfusion.toml，AI 生成）、编写（几行 WFL）、验证（wfl test / intent 回执）、度量（wfgen perf-diag --gate）—— 四个环节都有机器可读的接口与回执，于是「AI 生成 → 引擎回执指出差在哪 → AI 据回执修改 → 再验证」可以自动跑起来， 人只负责定义意图与验收标准。

AI 原生规则开发闭环

编译期检查

wfl lint / wfl explain

语法 / 类型错误在运行前拦住；编译后规则结构人 / AI 可读。

语义自证

wfl test （契约测试）

expect 是独立语义 oracle，引擎状态机进程内执行、秒级反馈；AI 改规则没改期望 → FAIL。

对抗测试生成

wfl test --gen-negatives

机器从规则结构静态反演反例，断言独立于 AI 写的 expect —— 打破「AI 写规则 + AI 自证」。

检测意图验证

wfl intent（.wfi 样本）

证明「意图本身对」：正样本 0 命中 → 漏报 FAIL；负样本命中 → 误报 FAIL。

真实回放 / 对拍

wfl replay / wfl verify

真实数据流 + oracle 逐条比对，支持 score / time 容差。

性能护栏

wfgen perf-diag --gate

语义对还不够，性能可接受才放行：绝对阈值兜底 + 相对基线防回归，门禁防静默失效。

生态设施

S
wf-skills 技能包

规则编写 / schema / 配置 / 测试管线 / 性能基准 / 集成接入，一键装入 Claude Code 或 Codex

R
wf-rules 规则语料

18 条按攻击阶段组织的真实 .wfl 检测规则，few-shot 语料 + 回归基线

E
编辑器 / LSP

tree-sitter-wfl 语法高亮 + WFL LSP（诊断 / 跳转 / 补全），AI 与人共用反馈通道

D
wfgen 确定性数据

同 count + seed 字节级确定；命中 / 近失 / 未命中三类样本，供回归与 AI 练习

诚实的边界：① AI 生成 ≠ 免验证——检测规则出错是静默的（漏报 / 误报不报错）， 生成规则必须跑 wfl test 并纳入回归；② 本闭环不做自动修规则——只承诺回执能证明 「对在哪、错在哪」，自动修复是回执之上的策略层；③ L2 反例生成只覆盖简单 bind guard，复合 guard 如实跳过、 不虚报覆盖；④ 当前为 alpha（2026-09），统一合并回执命令仍在演进。
