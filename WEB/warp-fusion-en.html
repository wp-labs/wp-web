Core Features

M

Cross-event pattern matching

Correlation across multiple events and time windows — structured event streams in, alerts / scores / structured data that match the conditions out.

L

WFL declarative language

Five primitives (Bind / Match / Stats / Join / Yield); the three-file model separates data definitions / matching rules / resource requirements.

B

Single binary · zero dependencies

Written in Rust — one binary runs the whole pipeline with no Kafka: roughly a thousand rules on a single 8GB node, idle memory target <100MB.

T

Rules ship with tests

`test` blocks live inside the rule file: hit / miss paths are verified; replay / verify / wfgen close the loop.

A

AI Native

The language is designed for AI generation: explicit semantics, machine-readable receipts — “AI writes the rule, the engine proves it, receipts drive iteration” as a first-class workflow.

R

Interpretable · scored

Entity modeling entity() + numeric scoring score() + stat.* evidence fields produce auditable alert evidence.

Rule Capabilities

WFL makes detection semantics first-class: temporal chains, missing-event detection, entity modeling, scoring, window stats and joins — one rule says what you are looking for

Five primitives · WFL — one rule, one attack chain

chain_attack.wflrules carry their tests 
// same IP: scanned 5 ports AND failed login 3 times within 30m → score 90
rule chain_attack {
    events {
        scan  : conn_events && action == "syn"
        login : conn_events && action == "login_fail"
    }
    match<sip:30m> {
        on event {
            scan  | count >= 5;
            login | count >= 3;
        }
    } -> score(90.0)
    entity(ip, scan.sip)
    yield network_alerts (sip = scan.sip, alert_type = "chain_attack")
}
test, in the same fileverify as you write 
// expect is an independent semantic oracle: change the rule, miss the expectation → FAIL
test full_chain for chain_attack {
  input {
    row(scan,  sip = "10.0.0.1", action = "syn",        event_time = "2026-01-01T00:00:00Z");
    row(login, sip = "10.0.0.1", action = "login_fail", event_time = "2026-01-01T00:00:05Z");
  }
  expect {
    hits == 1;
    hit[0].score == 90.0;
    hit[0].entity_id == "10.0.0.1";
  }
}
// wfl test rules/chain_attack.wfl --schemas "schemas/*.wfs"

WarpFusion is an AI-Native Engine

AI Native ≠ a built-in LLM: engine configuration, rule authoring, verification and measurement can all be done through AI

AI-native rule development loop

COMPILE-TIME CHECKS

wfl lint / wfl explain

Syntax and type errors are caught before anything runs; the compiled rule shape is readable by humans and AI alike.

SEMANTIC SELF-PROOF

wfl test (contract tests)

expect is an independent semantic oracle, executed in-process in seconds; change a rule without updating the expectation → FAIL.

ADVERSARIAL TEST GENERATION

wfl test --gen-negatives

Machine-derives counterexamples statically from rule structure, with assertions independent of AI-written expects — breaking the “AI wrote it, AI proved it” loop.

INTENT VERIFICATION

wfl intent (.wfi samples)

Proves the intent itself is right: a positive sample that misses → FAIL (false negative); a negative sample that hits → FAIL (false positive).

REPLAY / ORACLE DIFF

wfl replay / wfl verify

Replay real streams and compare every alert with the oracle, with score / time tolerance.

PERFORMANCE GATE

wfgen perf-diag --gate

Correct semantics are not enough — release only when performance is acceptable: absolute thresholds plus relative regression guards that cannot silently no-op.

SIEM / Security

🔗

Get Started with WarpFusion

Run a real example in three steps: install wfusion → clone the example → run nginx_log_stats

1 · Install wfusion (ships wfl / wfgen) 
curl -sSf https://get.warpparse.ai/inst-x.sh | bash -s -- wfusion alpha
2 · Clone the example repo 
git clone https://github.com/wp-labs/wf-examples
cd wf-examples/nginx_log_stats
3 · Run the example (live mode) 
./run.sh          # wfusion daemon + traffic injection (Ctrl-C to stop)
./view.sh         # second terminal: live dashboard http://localhost:8123/view/
